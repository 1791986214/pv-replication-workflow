# PV replication

先把原片的动作覆盖与用户故事改动写成整数帧合同，再补原画和合成。镜头的每一帧都需要有来源、状态与图层解释，但不要求每一帧都生图。源片 24fps 不等于每秒 24 张独特原画；帧率、独特绘图和持帧节奏分别记录。

## 开始与恢复任务

- 确认实际源媒体的 SHA256、帧率分数、总帧数、画布、音轨及最新交付 SHA256。旧会话的“最新版本”先核对文件与哈希。
- 帧区间统一为 `[start,end)`。秒数只供人阅读，不能用浮点秒驱动状态边界；变帧率源先约定时间戳到工作时间线的映射。
- 把用户要求转成有源事件、目标表情、姿态、局部动作、持帧范围的条目。源片动作与用户新剧情不同的地方写明改编，不能默默更换。
- 原画生成和人体审查由主智能体负责；重复抽帧、清单、缓存和确定性校验可并行交给子智能体。分工以明确的区间和文件所有权为单位。

## 拆解与补图

逐帧看一个连续镜头，标出独特 cel、重复帧和局部变化。分别记录头向、眼神、嘴、持物手、头发、衣摆、动物身体/尾巴、道具、歌词框、遮挡切换；不要从几张代表帧猜循环。先验证持物、转头、前景遮挡和变装等难镜头，再批量处理同类镜头。

- 每个源事件都要能找到目标绘图；每个目标绘图都要能追溯到一个源事件或获准的故事改动。不能以“已经生成了很多张图”代替动作覆盖。
- 分开姿态参考、角色设定参考和画风参考的职责。新图先验收头身比例、眼睛透视、下巴、膝盖/脚踝/鞋尖、服装与接触点，再注册进场景。
- 脸与头部不做光流拉伸。补表情时尽量由一张完整头部拥有帽、发、脸、下巴与颈部；清掉旧 owner 后用同一组注册参数放入全部差分。整张立绘平移不能替代手部、头发与衣摆的局部 A/B 绘图。
- 固定批准的鞋袜左右、腿长、膝盖方向、鞋面透视、裙摆连接和持物锚点。只改允许的局部；别让每张补图重新解释全套服饰与人体。

## 合成与边界

用明确实例和语义区域定义所有权；颜色与连通组件只能找候选，不能决定“黄色就是蝴蝶”或“最大区域就是框”。源物体与新绘图不能同时拥有同一只手、兔子或帽子。图层顺序随接触和遮挡事件明确变更。

特效在完整画布上独立合成，需要时越过人物轮廓；不要沿人物矩形或 alpha 裁掉烟团。若变装要在爆炸后发生，先验证换装差异完全被遮住，再在遮盖区间内换图。本片的四张绘图各持六帧只是实例，下一片按实际源节奏拆分。

合同字段、模板和校验命令见 [references/contract.md](references/contract.md)。运行：

```bash
python3 scripts/validate_contract.py contract.json
python3 scripts/validate_contract.py contract.json --stage delivery --root /path/to/project
```

校验器检查声明覆盖、帧界、状态顺序、owner、证据文件和哈希。它不能判断眼睛是否好看、烟雾是否真的不透光、尾巴是否活泼，也不会从一条 `actual_playback=true` 推断真的看过。

## 迭代、验收与交付

- 按采用原画哈希、帧合同、遮罩/跟踪版本、合成器版本建立缓存依赖；只重渲受影响区间以及前后事件边界。
- 优先输出短片原速、半速与源片同步对比，检查最终 MP4 的全部变动帧和连续播放。原速检查节奏，半速检查接触与跳变；静态联系表不能替代播放。
- 独立审查者先看源片连续动作和最终片段，记录范围、时间、文件哈希与具体发现，不能只复述作者的自评分。争议或新发现解决后再交付。
- 只改片段时可尝试实际 GOP 边界局部编码。拼接必须验证 PTS、帧数、解码和音轨；失败则回退到现有 MP4 的解码帧合片，不重做全片图像合成。压缩音轨可以原样复制时用 copy。
- 每次交付标明检查范围与未检查范围。机器通过不是“全片无缺陷”。保留最新成片、采用资产/提示词、合同、源码和验证记录；清理先 dry run 和依赖核对，别把参考图/旧 owner 资产误删。
- 恢复预检可运行 `python3 scripts/verify_recovery.py recovery-manifest.json --root /path/to/project`；它只核对用户提供的基线/补丁清单与文件哈希、整数帧覆盖，不解码或重建影片。旧冷缓存或旧打包依赖已移除时，明确退役入口和替代路径，不能声称所有旧命令仍可运行。

本 skill 不扩大外发邮件、发布仓库或原作素材的授权。发布代码时单独筛选源文件和许可；音乐、PV、角色原画不随代码 MIT 开放。
