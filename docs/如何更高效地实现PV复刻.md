# 如何更高效地实现 PV 复刻

效率来自更早确定缺什么原画、动作发生在哪一帧、谁遮住谁，以及只重做真正受影响的部分。换 AE、换模型、增加生图数量都可能有帮助，但不能自动修复没有拆解的手势和眼神。

本流程面向保留原 PV 时间线的角色替换与有限差分动画。大幅连续转身、复杂口型、透视变化或新的长动作，需要另外评估作画与动画方案；不要把它们承诺为“几张立绘加光流即可”。

## 1. 把原片读懂，再决定生多少图

从实际媒体锁定帧率、总帧数、画布、时间戳和音轨哈希。源片 24fps 是每秒播放 24 帧，可能每张绘图持续六帧，也可能头发 A/B 交替而手部在另一相位改变。独特原画数、局部差分数、绘图持帧、物体运动轨迹是四个不同的量。

按完整镜头逐帧记录，不仅保存第一张、最后一张和好看的代表帧。相邻帧差分、pHash 或光流可筛出候选变化；它们无法判断嘴究竟吹了一次还是两次，也无法区分画面缩放、头发摆动与姿态变化，最终仍需读连续动作。

每个镜头至少回答下表。原片没有的改编单独标明来源于用户剧情要求。

| 项目 | 要记录什么 | 常见漏项 |
| --- | --- | --- |
| 独特 cel 与持帧 | cel 源帧、起止、相位与重复范围 | 把源片重复帧算成新原画；把交替 A/B 当静态 |
| 头与脸 | 头向、倾斜、睁闭/半睁、瞳孔朝向、嘴形与切换帧 | 醒来没有睁眼、左右看反、一次吹气变两次 |
| 身体与服饰 | 肩、肘、腕、手势、衣摆、左右袜、脚尖方向 | 固定立绘替代手臂动作；杂耍每张裙子不同 |
| 局部循环 | 头发、袖口、呼吸、耳朵、动物身体和尾巴的 A/B | 只做整图平移；一条尾巴旋转代替两张尾形 |
| 接触 | 持杯、绳连接、帽在头上还是手上、手臂相互遮挡 | 手上取帽却头上还有帽；拥抱手臂中间被遮没 |
| 道具/歌词/框 | 单一实例、轨迹、框边、文字保留、消散过程 | 兔子重复、帽提前消失、歌词被清人物遮罩删掉 |
| 层序变化 | 谁在前，遮挡在哪帧改变，特效覆盖哪里 | 烟团被人物矩形裁断；原道具回贴带回旧手 |

这张清单的产物应能驱动生成任务和渲染器。不能只把它作为写完就不再读取的文档。

## 2. 用户要求变成可执行的帧合同

使用左闭右开整数区间 `[start,end)`。先将用户的秒数定位到实际源动作，再签入合同；不要直接按小数秒取整后猜表情。源动作、用户改编和目标绘图各有独立字段。

合同包含源事件、目标姿态/表情、采用 cel、相位 schedule、owner、层序、变装窗口和验收范围。建立双向覆盖：

- 从源事件出发，检查每个必要姿态和局部相位都有目标绘图。
- 从目标绘图出发，检查每张图实际被哪个源事件和帧区间消费；没有消费者的候选不算“已完成”。

这比按“已经生了多少张图”报告进度更可靠。某些表情只出现六帧，也不能因持续时间短而跳过；连续帧理解错误时应先改合同，不能继续批量生成错误姿态。

[合同工具与模板](../skill/pv-replication/references/contract.md)提供轻量检查。它不具备渲染能力，不替项目验证视觉质量；真正的合成器应读取相同状态表，或导出可逐帧比对的实际选择记录，避免合同一套、代码另一套。

## 3. 先做难镜头，锁定身份、人体和接触

下一次先做几种代表片段：持物、转头、框内脸、双人接触、动物循环、变装。选片应覆盖不同风险，不能只选容易看起来成功的开场。用户已经批准角色设定时继续沿用，不重复创造新服饰。

生图参考分清职责：原片裁切控制构图和动作，批准设定控制身份、服装和身高，已采用画面控制线条、配色与阴影。提示词记录所用参考和范围；工具不返回底层模型名时，不把图标成某个猜测的型号。

先审查完整原画，再看局部放大：眼睛近远透视、下巴/脸缘、头发遮眼关系、头身比例、膝盖朝向、脚踝到鞋筒、左右脚与鞋面透视、裙子腰线连接、手指/持物接触。右腿“无袜”或单侧连裤袜属于角色几何与服饰合同，不能由每次生成随机改写。

表情补图优先采用同构图的完整头部 owner；不要把不同透视的眼睛、嘴、脸、下巴分别糊在同一旧脸上。共用同一组注册参数，清除旧 head owner，检查所有差分的发缘与颈领接缝。只修嘴时若来源与旧脸透视不一致，宁可补整头，也不要不断补局部缝隙。

光流可以测源片运动或稳定道具轨迹，不能拿它拉伸脸和头发冒充新动作。整体平移/旋转适合对应原片整体运动；手臂、头发、袖口与裙摆的局部变化需要实际差分或适合它们的骨骼/网格方案，最终以源动作和连续效果验证。

## 4. 图层所有权先于抠色

每个实例/区域只有一个当前 owner。手和杯可由联合原画提供，不能又回贴带旧手的源杯；动物、兔子、帽子、鸭子、框线也不能从两处同时提供。

颜色与连通组件适合作候选定位：同一个黄色可能属于蝴蝶、文字、框或衣服；最大连通组件也可能是人物与框粘连的结果。最后需结合物体语义、已知区域、实例边界、来源帧与前后遮挡，定位失败报出具体帧，不静默保留旧人物。

清人物遮罩与恢复层必须保护歌词和装饰。框内人物与外框线分开拥有；动物爬上帽子时按真实相位处理帽/兔遮挡，不能提前整块删帽。接触镜头需在动作边界逐帧检查物体交接和断臂/断指，而非只看稳定姿态。

特效应是独立完整画布图层。以本片 `[1631,1708)` 的四张爆炸 cel 为例，每张持续六帧：起爆、扩张、密集遮盖、开洞散去。第三張全遮盖时才切换 normal 形态；检查的是两套人物的实际像素差异区域，而非“烟雾大致在脸旁”。

机器可以计算换装差异区域，检查这些像素处 alpha 或覆盖率；阈值由画面决定并记录。之后还要实际看烟雾开洞、散去、脸/手/衣服是否提前露出。特效不得被人物 alpha 或矩形裁掉，不为适配 ROI 随意旋成竖板。

## 5. 小片段交付与增量合成

原画与遮罩通过后，先输出短片的原速、半速和原片同步对比。这样可以在批量生成下一类镜头前发现相位错误或新图比例问题。

缓存依赖键至少包含：源媒体哈希、采用资产哈希、状态合同版本、遮罩/跟踪参数、合成器版本与输出规格。记录每张资产的消费者镜头；换一个共享素材时重做所有消费者，不能只改当前截图。

抽帧和跟踪按所需镜头区间处理。只改 77 帧就重渲这 77 帧，并在编码预览中加入前后切镜。相同 PNG 不重复存多份；审阅图可重建，压缩截图只保留关键证据。不要把大量 PNG 写盘、生成联系表和整片重编码混成一条不可定位的长任务。

片段合入完整 MP4 时，可以先读取真实关键帧/GOP 边界，局部编码覆盖 GOP，外段 stream copy。但片段拼接后必须核对帧数、PTS 连续性、完整解码、边界与原音轨。失败时回退到既有 MP4 解码帧重新编码视频，并替换指定帧；这比重新合成全片所有图层便宜。原音轨不变且容器/编码允许时用 audio copy 并校验压缩载荷。

本片局部 stream copy 实际未通过帧数校验，最终采用解码视频回退。没有证据说明局部方案普遍会成功；也没有量化工时/token节省比例，不能把建议写成已实现的倍数提升。

## 6. 原速、半速、逐帧与独立审查分别负责什么

| 检查 | 能发现 | 不能替代 |
| --- | --- | --- |
| 原画放大 | 脸线、眼睛、人体、鞋袜、服装和裁切边缘 | 动作节奏、相位与遮挡变化 |
| 状态边界逐帧 | 错帧、跳位、露换装、断手、提前遮帽、缺字 | 原速连贯与表演感 |
| 实际最终 MP4 原速 | 剧情节奏、吹气次数、微动是否可感知、连贯性 | 局部线条与音轨载荷校验 |
| 实际半速 | 接触、跳变、循环相位、烟团边缘 | 原速时的观感 |
| 独立审查 | 盲点、作者与实际目标不一致 | 用户的最终美术选择 |
| 机器检查 | 帧覆盖、哈希、尺寸/fps、PTS、解码、音轨、未改范围 | 人体、画风、表情和故事效果 |

记录实际检查过的 MP4 SHA256、帧范围、播放模式、审查者、发现与证据。抽帧网格通过不能记为“已经完整播放”；浏览器权限失败也不能记为播放通过。用户已授权时解决真实阻碍或切换合适的已允许播放工具，不反复问同一权限。

独立审查者应得到源连续帧、目标最终片段和需求，先给具体问题及帧号，再与作者结论核对；不让它只确认作者列出的成功项。作者仍负责验收和交付，子智能体执行并不转移质量责任。

发布版本前核对视频真接到了最新文件，而非仅页面标签更新。多人/多会话协作冻结输入哈希、区间和负责人，合并后检查两个切镜及对方已选表情是否仍在。视频形式没有变化不表示内容就没变化。

## 7. 保留可复现骨架，再清理冗余

保留最新正片与源媒体、采用原画和差分、提示词/参考定位、owner 与遮罩/跟踪配置、整数帧合同、渲染/编码源码、音轨与媒体哈希、验证/播放记录、依赖说明，以及仍被构建引用的旧素材。

先生成文件清单和大小，按采用资产依赖闭包与消费者定位保留范围。清理计划列出可重建缓存、重复副本、失败 partial 输出、淘汰预览；dry run 后核对最新交付和采用资产哈希，再删除明确冗余项。没有消费者证明的素材不因“旧版本”命名直接删除。归档不是免费空间，巨型重复 ZIP 也要核对内容后处理。

公开 GitHub 只发布代码、合同空模板、技能与经验文档；私有角色图、原片、音乐、邮件地址、绝对用户路径和缓存不随代码进入仓库。最终保存发布清单与版本映射，便于下一次恢复。

## 经验是否有效，下一项目这样衡量

记录每轮补图数、采用率、动作遗漏数、人体/服装返工数、每类问题首次被发现的阶段、渲染/编码时长、缓存命中率和可取得的模型用量。若没有日志就记未知，不能估算成精确数字。

优先目标不是“多生成图”，而是生成前动作合同完整、注册前人体批准、批量前难镜头通过、交付前实际 MP4 与独立审查闭环。下支不同 PV 需要验证这些步骤的实际成本，再把稳定接口抽成通用渲染库。
